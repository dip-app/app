# iOS workspace

Install Xcode and XcodeGen (`brew install xcodegen`). From the repository root run `npm run ios:generate`, then open `ui/DIP.xcodeproj` and choose the DIP scheme. Commit `project.yml`, not generated project files. This avoids shared project-file conflicts. The target is iOS 17+, Swift 6; the minimum OS and final bundle identifier are proposed team decisions. Set your signing team locally in Xcode for device runs.

This target combines Google onboarding with the native prototype. DIPAccounts and the compiled FirebaseAccountsRepository now provide account-session/repository behavior, and `FirebaseBootstrap` (DIP/Support) attaches Firebase and Google sign-in when local configuration exists (ADR 0007); onboarding comes first and its member state opens Home. To connect the real project: put its `GoogleService-Info.plist` in `ui/DIP/Support/`, copy `ui/Config/Local.example.xcconfig` to `ui/Config/Local.xcconfig` and set `GOOGLE_REVERSED_CLIENT_ID` from the plist's REVERSED_CLIENT_ID, then run `npm run ios:generate`. Both files are gitignored; never commit them or service account credentials. Without them Debug uses the in-memory preview account flow, while Release reports that sign-in is not configured. Home and its event/profile/gallery flows currently use the mock adapter even with Firebase configured; live tenant content is not implemented. To use the local emulators in Debug, set `DIP_USE_EMULATORS=1` in the scheme's environment. App Check: on first launch a Debug/Simulator build prints `Firebase App Check debug token: ...` in the Xcode console; add it in Firebase console -> App Check -> Apps -> Manage debug tokens so deployed callables accept that simulator. Running on your own iPhone from Xcode (a Debug build, free Personal Team) also uses the debug provider: register that device's printed token too. Release builds use App Attest, which needs a paid Apple Developer team plus the entitlement noted in `FirebaseBootstrap`. Emulator host is 127.0.0.1 on Simulator; physical devices need the laptop LAN address. Never connect a development build to production by default.

`DIPContracts` contains generated Foundation DTOs. `DIPDesignSystem` contains token foundations. These packages and DIPAccounts test independently of an iPhone simulator. JSON dates use ISO 8601 UTC; Firestore persistence uses Timestamp via explicit adapters in Data; the account adapter supplies the first mapping. Document IDs belong to snapshot metadata; optional `id` is injected by the adapter and is not a Firestore field.

Use feature ViewModels and injectable repository protocols. Views render state and delegate actions; Firebase access lives in Data. Define the protocol and mock fixture together before separate agents build UI and adapters. Do not invent endpoints or duplicate shared tokens.

Full simulator build after generation: `xcodebuild -project ui/DIP.xcodeproj -scheme DIP -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build`. Full app tests: choose an available iPhone simulator using `xcodebuild -showdestinations`, then pass its destination to `xcodebuild test`. The feature test is explicitly skipped until work begins.

Read [V1 account integration](../docs/contracts/accounts-integration.md) before wiring AccountsSession. It explains configured SDK injection, token refresh after verification, listener disposal, profile limits and remaining device/App Check work. The full SDK app build is now required in CI; sources exclude Markdown documentation to avoid duplicate bundle-resource outputs.

Native Home/events/profile/album and photo comments are integrated from PR #3, with separate DIPCore/DIPPresentation/DIPMockData products and an isolated preview host. Preserve Google-only account contracts and server-owned OAuth display names when connecting those screens; prototype data is not a live company feed.

## Mock-member launch mode (Debug only)

Launch the real app without Google sign-in or Firebase: `xcrun simctl launch <device> org.dip-app.DIP --mock-member` (or set `DIP_MOCK_MEMBER=1`). It skips Firebase/App Check configuration, signs in a fixed fixture member (Sam Rivera, `company-demo`, in-memory `PreviewAccountsRepository`) and boots the real member shell (Home, Rewards, My Events, Profile) on `DIPMockRepository` with `DIPMockFixtures.v1Events()` (dated events with venue and address, so Directions shows). `--mock-onboarding` uses the same isolation but starts signed out, so the welcome and onboarding flow runs for a fresh uid. Both are compiled only under `#if DEBUG` (`ui/DIP/App/MockLaunch.swift`); Release ignores them, and nothing writes to Firebase or the keychain. UI test: `xcodebuild test -project ui/DIP.xcodeproj -scheme DIP -destination 'platform=iOS Simulator,name=<sim>' -only-testing:DIPUITests` (`ui/DIPUITests`).

**Replaying the onboarding tour (Debug only).** The tour is recorded per account (`dip.onboarding.v1.<uid>` in UserDefaults), so it normally plays once. In Debug builds, signing out (Profile's Sign out, or the tour's first-step Sign out) also forgets that account's record, so signing back in plays the whole tour again. To reset without signing out, launch with `--reset-onboarding`: every `dip.onboarding.v1.*` record is cleared once at launch (real app and Preview app). Release builds keep records across sign-out and ignore the flag. Other tour flags: `-onboarding.reset`, `-onboarding.resumeAt <step>`, `-onboarding.timeScale <n>`, `-onboarding.features all` (see `OnboardingTourSettings`).

**"Finding your company" minimum time.** The sign-in Stage keeps "Finding your company" up for at least `AccountsStage.minimumResolvingDuration` (2.0 s, rounded up to whole turns of the face wheel, so 2.2 s; 0.8 s with Reduce Motion), even when membership resolves instantly. It only pads: a slower resolution adds nothing, and notices (unmapped domain, offline, conflict) show right after the same minimum. Launch with `--no-resolving-delay` to turn it off (UI tests).
