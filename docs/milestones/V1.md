## Committed features and acceptance checks

| ID | Feature | Acceptance criteria | Lead area; named owner TBD |
| --- | --- | --- | --- |
| V1-01 | Google sign-in and company access | Sign in and out with Google through Firebase Auth; the server places the user in the company mapped to their work email's root domain, refuses personal email domains, and shows a clear state when the company isn't on DIP. Company content is inaccessible to another company's users. Company, role and display name cannot be edited by the client ([ADR 0007](../adr/0007-oauth-domain-based-sign-in.md)). | Accounts + backend |
| V1-02 | Basic profile and interests | View and edit the permitted profile fields and selected interest tags; saved changes persist after reopening. Editing does not alter membership, role, or points. | Accounts |
| V1-03 | Event discovery | Show upcoming events for the current company and open the selected event by its stable ID. Empty and failed requests have explicit states. | Discovery + frontend |
| V1-04 | Event details and attendees | Show description, date/time, duration, address, price, and attending coworkers. Use a clear attendee label and distinguish joining from attendance. | Discovery + frontend |
| V1-05 | Organizer event management | Manually authorized organizers can create and edit events; required fields are validated; ordinary members cannot perform organizer writes. Use the role spelling and write boundary defined by the contracts. | Organizer + backend |
| V1-06 | RSVP and cancellation | Join and leave an event; one RSVP identity exists per user/event; state remains consistent across screens and after reopening. Concurrent joins and repeated requests must follow the server contract. | Discovery + backend |
| V1-07 | My Events | Show the signed-in user's joined upcoming and past events; each item opens its matching details. Make dates and locations easy to scan. | Discovery + frontend |
| V1-08 | Default event imagery | Cards and details use category-based default images. Do not add user photo uploads to this milestone. | Frontend + design system |
| V1-09 | Standard event sharing | Open the iOS share sheet with useful event information. V1 does not promise that a shared link opens directly inside DIP and does not create an in-app invitation. | Discovery + frontend |
| V1-10 | Integration and usability | Navigation connects every V1 flow; loading, empty, and error states are handled. Use one clear Join action, visible joined confirmation, a recognizable My Events destination, and an active-tab indicator. | Frontend + all areas |
| V1-11 | Verification | Test key V1 logic with a target of at least 70% unit coverage; verify the project builds on another laptop and the core flow works on a physical device. Record coverage scope and manual evidence. | Every feature owner |

## Recommended implementation order

1. Agree on the account, membership, event, and RSVP contracts and their security tests.
2. Build sign-in/company access and shared data adapters; develop screens against contract fixtures in parallel.
3. Integrate discovery/details and organizer event management.
4. Integrate RSVP, My Events, profile editing, and sharing.
5. Verify the complete flow and address the recorded usability problems.

This order is repository setup guidance, not an additional requirement from the submission. No person is assigned by this document.

## Handoff checklist

- [ ] Assign one human owner to each feature issue and identify affected folders.
- [ ] Confirm callable contracts, direct Firebase access, and error behavior before integration.
- [ ] Add rule tests for unauthenticated, cross-company, and unauthorized organizer access.
- [ ] Test RSVP persistence, duplicate requests, cancellation, and concurrent joins.
- [ ] Check profile permissions and prohibit client changes to server-owned fields.
- [ ] Verify dates/locations, attendee labels, joined feedback, and tab recognition with users.
- [ ] Record meaningful unit coverage against the 70% target; do not count generated models as product logic.
- [ ] Record another-laptop build and physical-device verification.

## Outside V1

Google sign-in with email-domain company membership replaced email/password and join codes for V1 (ADR 0007, maintainer decision of November 1, 2026); Apple sign-in remains later work. In-app invitations, challenge participation/approval, points, uploads, interest filtering, chat, rewards, raffles, notifications, and venue/weather integration belong to [V2 or its stretch scope](V2.md). The prototype's visible challenge and rewards screens do not expand V1.
