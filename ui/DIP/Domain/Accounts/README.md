# Account domain boundary

`DIPAccounts` is a Foundation/Observation Swift package with no Firebase SDK dependency. `AccountsRepository` is MainActor isolated and exposes a cancellable `AsyncStream<AccountObservation>`. `AccountsSession` consumes it; call `start()` on activation and `stop()` when its owner ends. Stream termination removes SDK listeners. Unexpected completion clears membership with an unavailable error; restart generations prevent old observation or command completions from changing a new session. State transitions clear membership immediately for a different identity, sign-out, malformed profiles and listener failures. Events from previous UIDs are ignored. `MembershipContext` exposes uid, companyID, role and the observed AppUser. Roles are `member` and `admin`; server authorization remains authoritative.

`FirebaseAccountsRepository` lives in Data/Accounts. Inject configured Auth, Firestore and **Functions.functions(region: "us-central1")** instances after emulator setup; no project IDs or credentials are embedded. `signInWithGoogle()` uses the configured FirebaseApp's iOS client ID and GoogleSignIn, then signs in to Firebase Auth (ADR 0007: Google only). The own-profile listener uses users/{auth.uid}; refreshIdentity reloads the Auth user and forces an ID-token refresh before restarting that listener. AppUser is mapped explicitly from Firestore fields and Timestamp; snapshot ID is metadata. When a verified identity has no profile, AccountsSession calls `resolveMembership()` (resolveMembershipV1) once per identity; membership readiness comes only from the listener, never the acknowledgement. Personal domains, unmapped domains, conflicts and permission failures become `.noCompany` and never authorize a tenant. Refresh can retry failed listeners.

The editable profile intentionally has only photoURL, avatarId, department, jobTitle, city, interestTagIds, travelRadiusMiles and availability. displayName comes from OAuth and is server-written. Limits mirror the reviewed V1 rules: photo URL <=2048; avatar/department/title/city <=120; lists <=10 nonempty strings <=120; radius integer 0...500. These are feature validation limits, not generated-schema changes. Friend/favorite lists are V2. No JSON-encoded profile is persisted. updateData sends exactly this allowlist.

`commandError` is separate from observed state; retry commands after correcting input or transient failures. `isSubmitting` prevents duplicate submissions. Failed sign-out clears rendered membership immediately. Restart/refresh observation after recovery; errors never authorize a tenant. Callable errors map stable SDK codes to portable AccountsFailure values without exposing payloads or emails; a cancelled Google sheet is not an error. Tests use a controlled repository and make no claims about emulator/device completion.
