## Changes

- `transport/resolveMembershipV1.ts`: `defaultAdminApp()` returns the `[DEFAULT]` Admin app, creating it if missing. In production firebase-functions creates its own named app (`__FIREBASE_FUNCTIONS_SDK__`) while verifying the callable's Auth/App Check tokens, so the previous `getApps().length === 0` guard skipped `initializeApp()` and every call failed with "The default Firebase app does not exist" (HTTP 500). The emulator skips that verification, which is why integration tests did not catch it.
- `gcp/tests/unit/accounts-default-app.test.ts`: reproduces the production order (named SDK app first); fails on the old guard, passes with the fix.
- `infrastructure/firestoreMembershipStore.ts`: server-side warning logs when a domain mapping is missing or malformed, or points to a missing company (logs `rootDomain`/`companyId` only; never email or uid). The caller still receives one `NO_COMPANY_FOR_DOMAIN`, so no company data leaks.

## Validation

- Backend unit tests (59) and `tsc --noEmit` pass in the Linux workspace; the new test fails against the old guard.
- Deployed: `firebase deploy --only functions,firestore:rules`, then `--only functions` twice (fix, then logging).
- Logs before the fix: "Callable request verification passed" followed by the default-app error (500). After: 404 with "companyDomains mapping not found" for `rootDomain: "cmu.edu"`.
- Root cause of the 404 was data: the console collection had been created as `companyDomains ` (trailing space, `%20` in the console URL). Recreated as `companyDomains` with `cmu.edu`; sign-in then succeeded and reached member content.

## Decisions
