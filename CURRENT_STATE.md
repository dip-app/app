## Chat, push and change-history backend (review branch, November 10)

`feature/chat-push-backend` adds the `notifications` Functions module: activity-chat rules (going participants append own messages; no edit/delete; open until 24 h after the end), owner-only per-event notification levels (`all | changes | reminders | none`, default `changes` created on join by an RSVP trigger), `registerDeviceV1`/`unregisterDeviceV1` for a server-only FCM token registry, a reusable `sendPush` service, chat/event-change triggers, a 15-minute reminder scheduler (~24 h and ~1 h, exactly once) and a bounded `changeLog` on events (`updateEventV1` now also stores `updatedBy`). Unit, rules and emulator integration tests (`npm run test:notifications:integration`) cover it; nothing is deployed. Real pushes additionally need the paid Apple team's APNs key in Firebase and iOS push entitlements, and the iOS chat/preferences adapters are not connected yet. See [callables](docs/contracts/callables.md#notifications-chat-and-change-history).

## Event photo albums backend (feature/v2-remaining, November 11)

The `photos` Functions module adds `finalizeEventPhotoV1` and the `onPhotoCommentCreated` count trigger, Storage rules for album uploads (`companies/{c}/events/{e}/photos/{uid}/{slot}`, 20 create-only slots per member per event, <= 10 MiB, jpeg/png/heic, going RSVP after a scheduled event ended; same-company reads) and Firestore rules for album documents (same-company reads, server-only writes) and photo comments (own-author append). Nothing is deployed; the Storage rules need the cross-service Firestore permission granted on first deploy. See [callables](docs/contracts/callables.md#event-photo-albums).

## Shake to report (review branch `feature/v2-stream-c`, November 11)

Shaking the device (or Profile > "Report a problem") captures the screen and opens a report sheet: category chips, description (1,000 characters), screenshot toggle, optional app details (app version/build, iOS version, device model, locale, route kind and a random install id; never name, email or token), Send with sending/sent/queued/failed states, and an offline queue (5 per uid, 7 days, 2/8/30 s backoff, discarded on sign-out). It is limited to Debug and TestFlight builds, and `dip.shakeToReport.enabled` (default on, Profile toggle) switches the shake off. `BugReportSubmitting` has a mock and a Firestore + Storage adapter. `firestore.rules` gains create-only `bugReports/{reportId}` (verified member, uid == auth.uid, strict allow-list and size limits, no client reads) and `storage.rules` allows an owner-only JPEG at `bugReports/{uid}/{reportId}.jpg` (<= 400 KB, no reads); both have emulator tests. **Nothing is deployed.** The markup editor, shake prompt step and rate limiting are not built (rules cannot rate-limit; see the PR).
