## Changes

- `ui/DIP/Features/Accounts/AccountsOnboarding.swift`: `AccountsRoute` (pure mapping from `AccountsState` to screen: loading / auth(error) / verifyEmail / joinCompany / problem / member; sign-in-form failures stay on the form, all other failures go to a retry/sign-out screen, never to membership), `OnboardingValidation` (email/password present, password >= 6 on sign-up, code 1..64 and name 1..80 after trim), user-facing messages for every `AccountsFailure` and validation problem.
- `ui/DIP/Features/Accounts/AccountsRootView.swift`: renders the route; `memberContent` only for an observed `MembershipContext`; `AccountProblemView` (Try again = `start()`, Sign out); does not own the session lifecycle. Previews: signed out / verify / join / member.
- `AuthView.swift` (sign in / create account; sends the verification email after a successful sign-up because `signUp` alone does not), `VerifyEmailView.swift` (`refreshIdentity`, resend with "sent" notice, "not verified yet" notice, sign out), `JoinCompanyView.swift` (code + name; after the acknowledgement shows "Finishing up…" until the profile listener confirms membership).
- `AccountsStyle.swift`: token-only feature styling (from the superseded branch) with a generic message label; to be replaced by packet 01 components.
- `ui/DIP/Data/Accounts/PreviewAccountsRepository.swift` (`#if DEBUG`): in-memory `AccountsRepository` that emits identity/profile observations like the listener (demo accounts member@/new@/unverified@, password "password", code DEMO-2026; configurable delay).
- `ui/DIPTests/Accounts/AccountsOnboardingTests.swift`: routing for every state and failure class, validation, messages, and two flows driving the real `AccountsSession` over the preview repository (wrong password -> join with bad/good code -> member -> sign out; unverified -> verify -> join step).
