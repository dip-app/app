# Current development state

Last audited: November 3, 2026. Read Git/CI and the work tracker alongside this handoff.

PR #4's reviewed company-membership core is merged. Per ADR 0007, sign-in is Google-only and company membership comes from the email's root domain: `resolveMembershipV1` (production App Check, transactional per-UID throttling, personal domains refused) replaced joinCompanyV1 and join codes, and Firebase attaches through `FirebaseBootstrap` once local configuration is added. The integration adds narrow verified self-profile/company/tag rules, and provides DIPAccounts plus a compiled Firebase Auth/Firestore/Functions adapter. It has not deployed cloud resources or configured a real Firebase project. Other product callables and data paths remain unimplemented/denied.

**Admin portal (V1-05 preview).** `apps/admin` is a Next.js static export in mock mode (local data, no organizer callables yet), deployed by hand to Firebase Hosting at https://team05-dip.web.app (site `team05-dip`, `noindex`). CI builds and tests it; automatic deploy from `main` is wired but inactive until the `FIREBASE_SERVICE_ACCOUNT_TEAM05_DIP` repository secret exists. Deploy, preview-channel, rollback and credential steps are in [apps/admin/README.md](apps/admin/README.md#deploy-firebase-hosting). The Firebase project `team05-dip` also hosts the deployed `resolveMembershipV1` function, Firestore rules and indexes.

**Organizer backend (V1-05).** `createEventV1`/`updateEventV1` are implemented in `gcp/functions/src/modules/organizer` and exported, with unit tests, Firestore rules tests for event reads (same-company members: scheduled only; organizers: all; no client writes) and an emulator integration test (`npm run test:organizer:integration`, wired into CI). They are **deployed** to `team05-dip` (November 3, 2026, with the rules), and one maintainer account has the `admin` role. `apps/admin` has a Firebase adapter for them (Google sign-in, tags, event feed, both callables), proven end to end against the emulators (`npm run test:admin:live`, in CI); the web app, an App Check reCAPTCHA key and one organizer account are configured in `team05-dip` and the hosted portal (https://team05-dip.web.app) is deployed in live mode. A real browser sign-in plus create/edit against production has not yet been exercised. Per issue #14, any RSVP record (including cancelled) locks both the start and end time. See [callables](docs/contracts/callables.md#organizer-commands-implementation).
