# Email engineering runbook (reference)

Owner steps (Squarespace and Postmark) are in [email-setup.md](email-setup.md). This file is the longer engineering reference.

Status: nothing below has been done. The code ([email design](../design/stretch/email.md), [email contract](../contracts/email.md)) ships switched off: `EMAIL_ENABLED=false`, `EMAIL_PROVIDER=log`, no company enabled. Agents prepared this page; a human runs every step. Nothing here is free of judgment: provider choice, money and DNS are owner decisions.

Facts on November 17, 2026: `letsdip.work` has **no MX, SPF, DKIM or DMARC records**, and **`support@letsdip.work` does not exist**, although the landing support and privacy pages tell people to write to it. DNS is managed at the registrar ([deploy runbook](deploy-runbook.md), custom domain section).

Order: mailboxes first (the support address is already published), then the provider and DNS, then secrets and params, then a pilot. Allow a few days for DNS, verification and warm-up.

## 1. Inbound mailboxes (support@, notify@, dmarc@)

Pick one (prices are the design doc's; verify at purchase):

| Option | Cost | Notes |
| --- | --- | --- |
| Google Workspace Business Starter | about $7 per user per month | Real mailbox for `support@`; `notify@` and `dmarc@` as aliases or groups |
| Cloudflare Email Routing | free | Forwarding only; requires moving DNS to Cloudflare |
| ImprovMX | free (1 domain, 25 aliases) | Forwarding only, no sending |
| Zoho Mail free | free (5 users) | Real mailboxes |

Create:

- `support@letsdip.work`: human inbox (the Reply-To of every email and the address on the landing pages).
- `notify@letsdip.work`: the From address. Replies land here; forward to `support@` or auto-reply "this address is not monitored, write to support@".
- `dmarc@letsdip.work`: receives DMARC aggregate reports (forward to whoever reads them, or a DMARC report service).

Publish the mailbox provider's `MX` records exactly as it shows them. Only one set of `MX` records may exist on the apex; the sending provider below does not need apex MX (Postmark's bounce domain uses its own subdomain).

Check: send a message from a personal account to `support@letsdip.work` and confirm it arrives.

## 2. Sending provider (recommended: Postmark)

1. Create the Postmark account (owner; billing starts at about $15 per month for 10k emails; the free developer tier allows 100 emails per month for testing).
2. Create a server named `DIP` and inside it a **message stream** named `notifications` (type: Transactional). Keep account-critical mail, if it ever exists, in a separate stream (the code addresses streams by `POSTMARK_MESSAGE_STREAM`, default `notifications`).
3. Add the sender signature domain `letsdip.work` (Sender Signatures > Domains).
4. Postmark shows the DNS records to publish. They look like this (copy the exact values from Postmark, not from here):

| Type | Host | Value (shape) | Purpose |
| --- | --- | --- | --- |
| TXT | `<selector>._domainkey` (for example `20261117pm._domainkey`) | `k=rsa; p=MIGf...` | DKIM signing for `letsdip.work` |
| CNAME | `pm-bounces` | `pm.mtasv.net` | Custom Return-Path (bounce domain), gives SPF alignment |

5. SPF: with the custom Return-Path above, SPF is checked on `pm-bounces.letsdip.work` and Postmark covers it; no apex SPF change is required for Postmark. If the mailbox provider also sends as `@letsdip.work` (Google Workspace), publish one apex SPF record that includes only that provider, for example `letsdip.work TXT "v=spf1 include:_spf.google.com ~all"`. Never publish two `v=spf1` records.
6. Wait for Postmark to show DKIM and Return-Path as verified.
7. Request account approval in Postmark (new accounts are in test mode until approved).

Alternatives (only if the owner prefers): Resend (free 3,000 per month, 100 per day) or Amazon SES. Each needs a new adapter implementing `EmailProviderPort` and `EmailWebhookVerifier` (about 150 lines plus tests); the rest of the pipeline does not change.

## 3. DMARC

Publish after DKIM verifies:

```text
_dmarc.letsdip.work  TXT  "v=DMARC1; p=none; rua=mailto:dmarc@letsdip.work; fo=1"
```

After two to four weeks of clean aggregate reports (SPF or DKIM pass and aligned for all legitimate mail), move to `p=quarantine; pct=100`, later `p=reject` if nothing else sends as the domain.

## 4. Secrets (Secret Manager, project `team05-dip`)

Names only; values are generated by the owner and never committed, pasted into chat, or logged.

| Secret | Value | Used by |
| --- | --- | --- |
| `EMAIL_UNSUBSCRIBE_KEY` | 48 random bytes, base64 (`openssl rand -base64 48`) | `onEmailOutboxCreated` (signs links), `emailUnsubscribeV1` (verifies). Rotating it invalidates outstanding unsubscribe links: rotate only on compromise. |
| `POSTMARK_SERVER_TOKEN` | Postmark server API token (Server > API Tokens) | `onEmailOutboxCreated` |
| `RESEND_API_KEY` | Resend API key (`re_...`, sending access for `letsdip.work`); only with `EMAIL_PROVIDER=resend` | `onEmailOutboxCreated` |
| `RESEND_WEBHOOK_SECRET` | Resend webhook signing secret (`whsec_...`, Svix) | `emailWebhookV1` |
| `EMAIL_WEBHOOK_PASSWORD` | 32 random bytes, base64url (`openssl rand -base64 32 \| tr '+/' '-_' \| tr -d '='`), at least 24 characters | `emailWebhookV1` (Basic auth password; username is `dip-email-webhook`) |

```sh
firebase functions:secrets:set EMAIL_UNSUBSCRIBE_KEY --project team05-dip
firebase functions:secrets:set POSTMARK_SERVER_TOKEN --project team05-dip
firebase functions:secrets:set EMAIL_WEBHOOK_PASSWORD --project team05-dip
firebase functions:secrets:set RESEND_API_KEY --project team05-dip
firebase functions:secrets:set RESEND_WEBHOOK_SECRET --project team05-dip
```

**Deploy prerequisite:** the email functions bind these secrets, so a functions deploy fails (or prompts) while they do not exist. Before the first functions deploy that includes the email module, create all five (`EMAIL_UNSUBSCRIBE_KEY`, `EMAIL_WEBHOOK_PASSWORD`, `POSTMARK_SERVER_TOKEN`, `RESEND_API_KEY`, `RESEND_WEBHOOK_SECRET`). Each provider secret is bound only by the function that needs it (`onEmailOutboxCreated` binds the two API credentials, `emailWebhookV1` the two webhook credentials), but Firebase cannot bind conditionally on `EMAIL_PROVIDER`, so the unused provider's secrets need placeholder values such as `unset`. They are only read for the selected provider, and the Resend webhook verifier refuses a secret that is not a real `whsec_` value, so a placeholder can never authenticate a request. With `EMAIL_PROVIDER=log` none of them is used.

## 5. Params (`gcp/functions/.env.team05-dip`, not committed)

```text
EMAIL_ENABLED=false
EMAIL_PROVIDER=postmark   # or resend, or log
EMAIL_DEFAULT_TIME_ZONE=America/New_York
POSTMARK_MESSAGE_STREAM=notifications
EMAIL_OPEN_TRACKING=false
```

- No postal address param: the emails are transactional (invitations, updates, reminders and reviews the member opted into), and the footer gives `support@letsdip.work` as the contact. If a promotional email is ever added, a postal address or PO box becomes required (CAN-SPAM) before it ships.
- `EMAIL_OPEN_TRACKING=true` adds the approximate open pixel (`/o/<token>.gif`, function `emailOpenV1`). The privacy page already describes it; leave it off if you do not want it.
- `EMAIL_DEFAULT_TIME_ZONE` is used when `emailSettings/{companyId}.timeZone` is unset; every time in an email shows the zone abbreviation.

## 6. Webhook

In Postmark (Server > Message stream `notifications` > Webhooks) add a webhook to the function URL with Basic credentials embedded:

```text
https://dip-email-webhook:<EMAIL_WEBHOOK_PASSWORD>@us-central1-team05-dip.cloudfunctions.net/emailWebhookV1
```

Enable: Bounce (with "include message content" off), Spam Complaint, Subscription Change. Delivery is optional (logged as ignored). Use "Send test" for each type; the function answers 200 for a valid payload and 401 for wrong credentials.

## 7. Enable a pilot company

1. Firestore console, collection `emailSettings` (server-only), document id = the company id:

```json
{ "enabled": true, "dailyCap": 200, "timeZone": "America/New_York" }
```

2. Set `EMAIL_ENABLED=true` and redeploy the email functions only:

```sh
firebase deploy --only functions:dip:onEmailOutboxCreated,functions:dip:emailUnsubscribeV1,functions:dip:emailWebhookV1,functions:dip:emailOpenV1 --project team05-dip
```

   The account emails ([email catalog](../design/email-catalog.md)) also need `welcomeEmailOnMemberCreated` (welcome), `sendRosterInviteEmailV1`, `listRosterV1` and `updateBugReportV1` (roster invitation and problem report emails) and the admin portal build that shows **Send invite email**. `sendRosterInviteEmailV1` and `listRosterV1` read `EMAIL_ENABLED` too, so redeploy them after changing it.

3. Deploy Hosting so `/u/**` reaches `emailUnsubscribeV1` and `/o/**` reaches `emailOpenV1` (rewrites in `firebase.json`), and so `https://letsdip.work/img/email/{logo,header,footer}.png` are live before the first email (they are part of the site build).
4. Firestore TTL policies (one-time, like `inviteRateLimits.expiresAt`): `emailOutbox.expireAt` and `emailCaps.expireAt`.

```sh
gcloud firestore fields ttls update expireAt --collection-group=emailOutbox --enable-ttl --project team05-dip
gcloud firestore fields ttls update expireAt --collection-group=emailCaps --enable-ttl --project team05-dip
```

Rollback: set `EMAIL_ENABLED=false` (or `enabled: false` for the company) and redeploy the sender. Queued outbox documents are skipped and expire.

Reaper alert and index: `emailOutboxReaper` runs every 15 minutes and logs a warning `email.reaper` (fields `abandoned`, `staleQueued`, `errors`) only when it changed something or failed; alert on that log entry. Its stale-queued query needs the composite index `emailOutbox` (`status` ascending, `createdAt` ascending); deploy it with the Firestore indexes before relying on it (the sending pass uses a single-field range and needs none).

## 10. Resend as the sending provider (alternative to Postmark)

Selected with `EMAIL_PROVIDER=resend` (params file, then redeploy the email functions). Postmark and `log` stay selectable; switching is a param change, no code change. Owner steps are in [email-setup.md](email-setup.md#if-using-resend-instead). Facts below come from the Resend docs (November 2026); re-check limits at purchase.

- **API:** `POST https://api.resend.com/emails`, `Authorization: Bearer <RESEND_API_KEY>`, JSON body (`from`, `to`, `reply_to`, `subject`, `html`, `text`, `headers`, `attachments` with base64 `content`, `filename`, `content_type`, `tags`). Plain `fetch`, no SDK (`infrastructure/resendProvider.ts`). Open and click tracking are off by default for a domain; keep them off (our optional pixel is the only open signal).
- **Idempotency:** header `Idempotency-Key` = outbox id (max 256 characters, kept 24 hours). A repeat of an accepted request returns the original result instead of sending again; the same key with a different body is `409 invalid_idempotent_request`.
- **Tags:** `template` (template id) and `outbox_id`. Resend webhooks echo tags, not metadata, so `outbox_id` is how a complaint maps back to the member. Tag values allow only letters, digits, `_` and `-`; other characters become `_`, which can break the match for an unusual id, in which case the webhook falls back to members with that address.
- **Error classification** (`SendOutcome`):

| Resend response | Outcome |
| --- | --- |
| 200 with `id` | `sent` |
| 429 (`rate_limit_exceeded`, `daily_quota_exceeded`, `monthly_quota_exceeded`) | `retryable`, up to 5 attempts, then `failed` |
| 409 `concurrent_idempotent_requests` | `retryable` |
| 500, 502, 503, 504 (any 5xx) | `retryable` (safe: the idempotency key prevents a second send) |
| connection refused / DNS failure before the request left | `retryable` |
| other 4xx (400, 401, 403 incl. unverified domain, 422) | `rejected` (permanent); the code is `resend_<status>_<name>` |
| 409 `invalid_idempotent_request` | `unknown` (an earlier attempt may have been accepted) |
| timeout, reset connection, 200 without `id` | `unknown` (at most once, never retried) |

- **Limits:** 10 requests per second per team (more with a request to Resend). Free plan: 100 emails per day (resets at midnight UTC) and 3,000 per month, 1 webhook endpoint, 3 domains, 30 days of logs. The company daily cap (`emailSettings.dailyCap`, default 200) can exceed the free daily quota: set it to 100 or less on the free plan, or upgrade. A quota 429 is retried but will keep failing until the quota resets; the 5 attempts then end `failed`.
- **DNS:** Resend uses a `send` subdomain for SPF and bounces (`MX` and `TXT` on `send`) and a DKIM `TXT` at `resend._domainkey`. DKIM aligns with `letsdip.work`, so DMARC passes while the root SPF stays `-all`.
- **Webhook:** `POST https://us-central1-team05-dip.cloudfunctions.net/emailWebhookV1`. Resend signs with Svix: headers `svix-id`, `svix-timestamp`, `svix-signature` (space-separated `v1,<base64>`), HMAC-SHA256 over `<id>.<timestamp>.<raw body>` keyed with the base64-decoded part of the `whsec_` secret. The verifier compares in constant time, rejects timestamps more than 5 minutes from now (past or future, which also bounds replays), and answers 401 for a missing header, bad signature or malformed secret. Events handled: `email.bounced` (type `Permanent` -> suppression `hard_bounce`; other types ignored like soft bounces), `email.complained` (suppression plus all categories off), `email.delivery_delayed` and `email.delivered` (ignored). Resend retries failed deliveries, and every write is idempotent.
- **Switching:** set `EMAIL_PROVIDER=resend` and redeploy `onEmailOutboxCreated` and `emailWebhookV1` (`firebase deploy --only functions:dip:onEmailOutboxCreated,functions:dip:emailWebhookV1`). Roll back by setting `EMAIL_PROVIDER=postmark` or `log`. Update the privacy page "Service providers" sentence to name the provider that is actually live.


## 11. Calendar invites: manual test checklist

Calendar invites (docs/design/stretch/calendar.md, "Emailed invites") send `invite.ics` with `METHOD:REQUEST` or `METHOD:CANCEL` from `DIP Events <events@letsdip.work>`. Prerequisites: the sending domain `letsdip.work` is verified with the active provider (no new DNS; the `events@` mailbox need not exist), `EMAIL_ENABLED=true`, a pilot company in `emailSettings`, and `calendarInviteOnRsvp` and `calendarInviteOnEventUpdated` deployed. Do this once with your own mailboxes before announcing the feature.

Setup: create an event starting at least 2 hours from now with a venue name and street address. Use three test members whose profile emails are one Gmail, one Outlook.com or Microsoft 365, and one iCloud address (read them on Gmail web and Android, Outlook desktop and web, Apple Mail on macOS, Mail on iOS).

For each client:

1. **Join.** Join the event in DIP. Within about a minute an email "Calendar invite: title" arrives from DIP Events. Check: sender name and address, Reply-To `support@letsdip.work`, not in spam, the invite card or `invite.ics` attachment is offered ("Add to calendar", "Yes" or an "Add" button), the card shows title, time in your zone, location and no RSVP request. Add it; the entry has the link `https://letsdip.work/e/<id>`, a 30 minute alert and the DIP Events organizer.
2. **Update.** Change the start time (and then the location) as an organizer. An "Updated invite" email arrives; accepting it must move the existing entry, not create a second one.
3. **Leave.** Leave the event in DIP. A "Removed from your calendar" email arrives; applying it removes the entry (Gmail and Outlook show "Event canceled"; Apple Mail offers Remove).
4. **Rejoin** and confirm a fresh invite again lands on the same entry (higher SEQUENCE).
5. **Cancel the event** with two members going: both get "Canceled" and their entries are removed or marked canceled.
6. **Unsubscribe.** Use the one-click link in an invite email, then join another event: no invite arrives; the Profile > Notifications > Email "Calendar invites" switch shows off. Turn it on again from the app.
7. **No-send cases.** Join and leave within a few seconds (no email; the queued invite is skipped with reason `not_going` in `emailOutbox`); join a past event (nothing); set `emailSettings.enabled=false` (nothing).

Record in the PR or session log, per client: card shown or only an attachment, add works, update replaces, cancel removes. If a client shows only an attachment and cannot import it, the fallback is the provider's SMTP relay with a hand-built `multipart/alternative` message (not built). Also check the headers of one received message: SPF, DKIM and DMARC pass for `letsdip.work`, and `Content-Type: text/calendar; charset=UTF-8; method=REQUEST` is on the attachment part.

## 12. Manual test plan for the email catalog

The [email catalog](../design/email-catalog.md) lists every email. None has been sent for real. Run this once with your own mailboxes, after section 7 (pilot company enabled, `EMAIL_ENABLED=true`) and before announcing email to a company. Use two Google accounts on the pilot company's domain (A: an admin, B: a person not yet signed in) and the seed list from section 8 (Gmail, Outlook, Apple Mail; light and dark). For every email check: sender `DIP <notify@letsdip.work>` (calendar invites: `DIP Events <events@letsdip.work>`), Reply-To `support@letsdip.work`, not in spam, the shared header art, white card and footer art load, one button that opens the right page, the plain-text part (Gmail "Show original"), a working one-click Unsubscribe next to the sender, and the `emailOutbox/{id}` document reaching `status: "sent"` with no address stored on it.

1. **Roster invitation (English).** As A (portal language English), Roster > Add person with B's work address and leave "Email them an invitation now" on. B gets "A invited you to join <company> on DIP" with B's address in bold and **Get DIP** (`https://letsdip.work/`). The row shows "Invite emailed 1×, last <date>" and the audit log has "Emailed an invite to <address> (#1)".
2. **Reminder and limits.** Click **Send invite email** again on B's row within the hour: the dialog shows "An invitation email went out less than an hour ago". After an hour, send again: the subject starts "Reminder: join <company> on DIP". The sixth attempt is refused ("already got several invitation emails").
3. **Staff link and Spanish.** Switch A's portal language to Español (Your settings > Language), add an organizer C and email them: the email is in Spanish and the button is **Abrir el portal de administración** (`https://letsdip.work/admin/`).
4. **Invitation opt-out.** In C's email click **Dejar de recibir invitaciones** (or Gmail's Unsubscribe): the page says invitations stop; `emailInviteOptOuts/<entryId>` exists; **Send invite email** for C now says they asked not to get invitation emails. Delete that document to undo the test.
5. **Invitee already joined.** Queue an invitation for B, then sign in as B in the app before it sends (or check an older queued one): the outbox document ends `skipped` with reason `not_invited`, and no email arrives.
6. **Email off.** Set `emailSettings/<company>.enabled=false`: the roster shows **Get invite message** again (no Send invite email), Add person has no email switch, and the message dialog says to share the message yourself. Turn it back on.
7. **Welcome.** Sign in to the app for the first time as B (the profile is created): one "Welcome to DIP at <company>" email arrives; signing out and in again sends nothing more (`account_<company>_<uid>_welcome` exists once). An admin's first sign-in gets the admin portal step and button.
8. **Problem report resolved.** As B (TestFlight or Debug build), Profile > Report a problem. As A, Bug reports > that report > Status Resolved: B gets "Your problem report was resolved" with the date only (no report text). Set it to Triaged and Resolved again: no second email.
9. **Unsubscribe from all.** In B's welcome email click Unsubscribe and confirm "Unsubscribe from all DIP emails": every email switch in Profile > Notifications is off, and a later problem report resolution sends nothing (`skipped`, `all_off`). Turn the switches back on in the app.
10. **Existing event emails.** With B going to an event: change its time (an "Updated: <title> (time changed)" email with the old time struck through), turn on Reminders in Profile > Notifications > Email and wait for the about 24 hour and 1 hour reminders (none after the start), have a coworker invite B to an event ("<name> invited you to <title>"), and cancel an event ("Canceled: <title>").
11. **Calendar invites.** Run the section 11 checklist (join, update, leave, rejoin, cancel, unsubscribe, no-send cases) in every client of the seed list.

Record the result per email and client in the PR or session log: arrived, inbox or spam, rendering (light and dark), button target, plain text, unsubscribe.
