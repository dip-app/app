# Account domain boundary

`DIPAccounts` is a Foundation/Observation Swift package with no Firebase SDK dependency. `AccountsRepository` is MainActor isolated and exposes a cancellable `AsyncStream<AccountObservation>`. `AccountsSession` consumes it; call `start()` on activation and `stop()` when its owner ends. Stream termination removes SDK listeners. State transitions clear membership immediately for a different identity, sign-out, malformed profiles and listener failures. Events from previous UIDs are ignored. `MembershipContext` exposes uid, companyID, role and the observed AppUser. Roles are `member` and `admin`; server authorization remains authoritative.

`FirebaseAccountsRepository` lives in Data/Accounts. Inject configured Auth, Firestore and **Functions.functions(region: "us-central1")** instances after emulator setup; no project IDs or credentials are embedded. The own-profile listener uses users/{auth.uid}; verification refresh reloads the Auth user and forces an ID-token refresh before restarting that listener. AppUser is mapped explicitly from Firestore fields and Timestamp; snapshot ID is metadata. Membership readiness comes only from the listener, never joinCompanyV1's acknowledgement. Refresh can retry failed listeners.

The editable profile intentionally has only displayName, photoURL, avatarId, department, jobTitle, city, interestTagIds, travelRadiusMiles and availability. Limits mirror the reviewed V1 rules: trimmed nonempty name <=80; photo URL <=2048; avatar/department/title/city <=120; lists <=10 nonempty strings <=120; radius integer 0...500. These are feature validation limits, not generated-schema changes. Friend/favorite lists are V2. No JSON-encoded profile is persisted. updateData sends exactly this allowlist.

`commandError` is separate from observed state; retry commands after correcting input or transient failures. `isSubmitting` prevents duplicate submissions. Failed sign-out clears rendered membership immediately. Restart/refresh observation after recovery; errors never authorize a tenant. Callable errors map stable SDK codes to portable AccountsFailure values without exposing payloads or join codes. Tests use a controlled repository and make no claims about emulator/device completion.
